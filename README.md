# Metal Stocktaking Telegram Bot

Telegram-бот для учёта операций с металлом и синхронизации данных с Google Sheets.

## Безопасный запуск

1. Создайте нового Telegram-бота или перевыпустите токен существующего через BotFather.
2. Создайте новый ключ сервисного аккаунта Google и дайте ему доступ только к нужной таблице.
3. Скопируйте `.env.example` в `.env` и заполните значения. Несколько Telegram ID в `ALLOWED_USER_IDS` указываются через запятую.
4. Сохраните JSON-ключ вне репозитория и укажите абсолютный путь в `GOOGLE_APPLICATION_CREDENTIALS`.
5. Установите зависимости: `python -m pip install -r requirements.txt`.
6. Запустите бота: `python app.py`.

`.env`, ключи Google, локальная база и загруженные фотографии исключены из Git и Docker-контекста. Бот прекращает запуск, если обязательная конфигурация отсутствует, и отклоняет сообщения пользователей, которых нет в `ALLOWED_USER_IDS`.

## Docker

Передайте `.env` через `--env-file`, а ключ Google смонтируйте только для чтения:

```bash
docker build -t metal-stocktaking-bot -f dockerfile .
docker run --rm --env-file .env \
  -v /secure/google-service-account.json:/run/secrets/google-service-account.json:ro \
  -v metal-bot-db:/app/db \
  metal-stocktaking-bot
```

## После утечки секретов

Старые Telegram- и Google-ключи считаются скомпрометированными даже после очистки истории Git. Их необходимо отозвать; повторно использовать старые значения нельзя.

## Известное ограничение зависимостей

Проект пока использует aiogram 2.25.2, который требует устаревшую ветку `aiohttp < 3.9`. Перед возвращением бота в публичную эксплуатацию следует отдельным изменением мигрировать обработчики и состояния на aiogram 3, а затем обновить aiohttp. До этой миграции запускайте бота только в режиме polling, не открывайте входящий HTTP-порт и сохраняйте ограничение `ALLOWED_USER_IDS`.
